# Rare fish variants (Silver / Gold)

Rare Silver and Gold fish have a soft glow outline, a few sparkles and a
small label; species colors and details are left alone. The variant is
**rolled once**, when a logical fish is created, and carried unchanged
through the river, the rod reveal, the aquarium, release, net catch, grinder,
every meat piece, carrying, trucks and customers. It is never rerolled.

**Money: nothing is paid.** The place has no currency consumer, so value
exists only as metadata until `ServerScriptService.FishPayout` is connected
(see [Still missing](#still-missing)).

## Defaults (tentative)

| Variant | Chance per new fish | Sale value | Look |
|---|---|---|---|
| Gold | 0.5% | ×5 per meat piece | gold outline, 4 sparkles/s, "GOLD" |
| Silver | 2% | ×2 per meat piece | silver outline, 3 sparkles/s, "SILVER" |

The two are mutually exclusive. The grinder's `meatFor(tier)` piece count is
unchanged and every piece carries the multiplier, so a fish's total value
scales ×2 or ×5. Tune these in `src/FishVariants.luau` (`Defs`).

## Install order (Studio, Edit mode, Command Bar)

1. Aquarium (already installed)
2. Fish jump (optional, independent)
3. `tools/fish-variants/InstallFishVariants.lua` (generated), one undo step

**Uninstall:** run `tools/fish-variants/UninstallFishVariants.lua`
**before** uninstalling the aquarium. It restores every recorded source and
refuses if any was edited after install. (The aquarium uninstaller would
refuse anyway, because RodFishingSystem no longer matches its patched copy.)

The installer changes nothing unless every check passes. It requires exactly
one Script each for:
- FishSpawner
- RodFishingSystem (must be the aquarium version)
- NetLiftScript
- GrinderProcessor
- TruckSystem
- CustomerSystem

Each must match its reviewed base source in `studio/`. The installed
aquarium modules must be v1, in which case they're upgraded to v1.1, or
already v1.1.

## What changes

Each patch is generated by `build/make_patches.py` from the base source.
Every edit is marked `FishVariants` and asserted to match exactly once.

| Script | Change |
|---|---|
| FishSpawner | Rolls the variant for each new fish and sets the `Variant` attribute and effects before parenting. |
| RodFishingSystem | Rolls at the final pick. The variant goes to the aquarium as meta; the glow appears only on the full-colour reveal, never the silhouettes; the grinder fallback passes it on. |
| NetLiftScript | `FishCaught:Fire(player, name, tier, { Variant, Source = "Net" })`. The 4th argument is new and ignored by 3-argument listeners. |
| GrinderProcessor | Reads the payload; each meat piece gets `Variant`, `ValueMultiplier` and a glow. |
| TruckSystem | Carried meat now keeps an `items` list next to `count`, so pieces aren't reduced to a number. Pickup captures tier/owner/variant before destroying the stack piece; delivery pops the top item. `MeatDelivered` gains a 3rd argument with the sale info. `FishPayout.onSale` is called once per delivered piece. Carried and loaded meat glow. |
| CustomerSystem | Tier/owner/variant are read **before** `giveMeat` destroys the meat. Previously `Tier` was read after `Destroy`. `CustomerBought` gains a 3rd argument. `topOfStack` still marks `Sold` first, so each piece sells exactly once, and `onSale` is called once. |
| Aquarium v1.1 | `SharedTank` carries whitelisted meta (`Config.Scene.PassthroughAttributes = { "Variant" }`) through the tank. Tank markers and fish released into the river get the same `Variant`. The tank client shows the effects. |

**Added**, all tagged `FishVariantsOwned`:
- `ReplicatedStorage.FishVariants` (pure rules)
- `ReplicatedStorage.FishVariantVisuals` (effects)
- `ServerScriptService.FishPayout` (returns nil)

Without these modules, every patched script behaves like its base.

## Still missing

1. **No base currency or payout.** No script pays for sales. To connect one,
   make `FishPayout` return
   `{ onSale = function(info) ... end }`. `info` holds:
   - `kind`, `fishName`, `tier`, `variant`, `multiplier`
   - `ownerId` (catcher), `sellerId` (truck deliverer), `customer`

   A base price per tier also has to be decided.
2. **What puts meat into `Workspace.SaleMeat`?** `CustomerSystem` sells from
   `SaleMeat`, but the grinder stacks into `MeatStack`, which trucks read.
   None of the supplied scripts fill `SaleMeat`. If that script moves the
   same meat part, the variant carries through. If it clones new meat, the
   variant is lost at that step and customer sales count as normal. Please
   send that script's source.
3. **Highlight limit:** Roblox renders at most 31 Highlights per client.
   Variants are rare (about 1–2 in a 60-fish river) and meat uses
   light/sparkles instead, so this should hold. If more are on screen, the
   extra outlines are skipped; sparkles and lights still show.

## Checks run

- `luau tools/fish-variants/tests/variants.test.luau`: 31 offline checks
  pass. They cover:
  - roll boundaries and measured rates (0.495% / 1.965% over 400k rolls)
  - sanitization and the payload round trip
  - sale info read from meat attributes, with junk rejected
  - coherent total value per tier
- Aquarium tests: 861 pass, including the new meta pass-through checks.
- Every patch, module and installer compiles and type-checks. The only
  remaining lints are same-line style warnings on unchanged base lines.
- The installer contains every source verbatim.
- **No Roblox runtime test yet.** Playtest suggestion: temporarily raise
  `Defs.Gold.Chance` to 0.5, then follow one gold fish from river → net →
  meat → truck, and one from rod → tank → release → net.
