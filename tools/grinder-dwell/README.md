# Grinder roller dwell

Fish arriving at the grinder now land on top of the rollers, tumble and
shudder there for about a second, then spiral in and shrink, as before. No
gore. Everything happens at the same `GrinderPos`, and aquarium routing is
unchanged.

## Timeline

`ReplicatedStorage.GrinderDwell` is the single source for every path:

| Phase | Seconds | Notes |
|---|---|---|
| rise | 0.12 | original |
| fly | 0.95 | original, ends exactly at `GrinderPos` |
| **dwell** | **1.0** | new |
| drop | 0.55 | original spiral and shrink |

- **Server timing:** the server destroys the fish and fires `FishCaught`
  once, at `serverDelay()` = 2.65 s. That's the client's 2.62 s plus the
  original 0.03 s slack; before the patch it was 1.65 s.
- **Dwell motion:** the fish settles from `GrinderPos` to `OffsetY` (−0.8)
  over 0.15 s. It then shudders upward only (≤0.12 studs, fading in and out)
  and tumbles at 4 rad/s. It drifts to exactly where the spiral starts, so
  the drop no longer snaps 1.2 studs sideways as the original did.
- **Per-fish:** everything is a pure function of the fish's own time and
  seed, so overlapping catches share no visual state.

**Tuning:** edit `Dwell` or `OffsetY` in the module. Raise `OffsetY` if fish
clip into the housing, lower it if they hover. It's placed relative to
`GrinderPos` because I haven't seen the roller geometry.

## What changes

Patches are generated by `build/make_patches.py` for every version that can
be live. Edits are marked `GrinderDwell`.

| Script | Accepted versions | Change |
|---|---|---|
| FishSwimClient | fish-jump patched, original | Adds the dwell phase to the `CaughtT` launch; the jump start point is kept. |
| NetLiftScript | fish-variants patched, original | `task.delay(1.65)` becomes `task.delay(Dwell.serverDelay())`; fires once with the payload unchanged. |
| RodFishingSystem | rod-cast (variants or aquarium), variants, aquarium | The grinder fallback plays the same dwell and drop server-side before `FishCaught` fires once. |

Without the module, all three behave exactly like their base versions.

## Install and uninstall

- **Install:** `tools/grinder-dwell/InstallGrinderDwell.lua` (generated). One
  undo step. **Install it last**, and **uninstall it first**
  (`UninstallGrinderDwell.lua`): the other features' installers and
  uninstallers refuse scripts this has patched.
- **Build-time sync check:** building the installer verifies that every
  patched client takes its timeline from the module and every patched
  NetLiftScript uses `serverDelay()`.

## Checks run

- `luau tools/grinder-dwell/tests/dwell.test.luau`: 20/20 pass. They cover:
  - totals and server slack, and phase order
  - continuity at both ends of the dwell
  - the dwell's largest per-frame move is 0.14 studs at 60 fps, and the drop
    never exceeds the original whirl speed
  - the fish stays on the rollers during the dwell
  - per-fish independence
  - the drop equals the original formula at `OffsetY = 0`
- All 8 patch variants and both installers compile and type-check; the only
  findings are lints on unchanged base lines.
- **Not Roblox runtime tested.** In Studio, check:
  - netted fish sit on the rollers about 1 s before disappearing
  - meat still appears once per fish
  - a rod catch with the aquarium off does the same
  - overlapping catches look independent
